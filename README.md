# Celinaz Worship

A worship-services web app for Celinaz — fully independent from `celinaz-attendance` (own repo, own database, own deployment).

## Status: live at https://celinaz-worship.vercel.app

Stack: Next.js 16 (App Router), React 19, Tailwind v4, NextAuth v5 (credentials + JWT sessions), Drizzle ORM + Neon Postgres, deployed on Vercel. Font is Apple's Noteworthy on Mac/iOS (where it's installed system-wide), falling back to Comic Neue elsewhere — Noteworthy isn't licensed for web embedding, so it can only be requested, not bundled.

## What it does

Built from the owner's real Mac Numbers spreadsheet and Mac Notes order-of-service doc:

- **Service Log** (`/log`) — every Sunday, oldest to newest, with inline editing per row.
- **Add Service** (`/add-service`) — a Sundays-only calendar picker, song autocomplete from the library.
- **Order of Service** (`/order-of-service`) — an editable run-sheet template per date: reorder/insert/remove items, an assignee field with addable/removable quick-pick pills, "start from last week" (copies structure, clears songs), "pull songs from Service Log," and a working Print view. Every saved date is browsable from **History** (`/order-of-service/log`).
- **Search** (`/search`) — by title, hymn #, or date, with "also played that Sunday" cross-references.
- **Song Library** (`/songs`) — every hymn/chorus ever used, sortable, with usage counts.
- **Shortlist** (`/shortlist`) — songs under consideration, not yet in the log.
- Click any song anywhere (except while building a new service) to queue it straight into an upcoming service.

Historical data (49 services from the owner's spreadsheet, Jan–Dec 2026) has a ready-to-run import: `npm run seed:worship-data`.

## Before this runs anywhere

- `npm install`
- A Neon Postgres database → `DATABASE_URL` in `.env.local`
- `AUTH_SECRET` in `.env.local` (generate with `openssl rand -base64 32`)
- `npm run db:migrate` (applies `drizzle/0000_flippant_power_man.sql`)
- `npm run seed:worship-data` (imports the historical spreadsheet data + song catalog)
- `ADMIN_NAME=... ADMIN_EMAIL=... npm run seed:admin` (creates the first sign-in user; prints a temporary password)
- Deploy: connect the GitHub repo (`menyart09-cloud/celinaz-worship`) to a Vercel project, set `DATABASE_URL` and `AUTH_SECRET` there too.

All of the above was verified end-to-end against a real local Postgres during development (migrations, seed import, every page, inline editing, the song popover, sorting, search, the calendar picker, print view) — it just needs real Neon + Vercel credentials to go live.

## Working conventions carried over from celinaz-attendance

- This Next.js version has breaking changes vs. training data — read `node_modules/next/dist/docs/` before writing Next.js-specific code.
- `AGENTS.md`/`CLAUDE.md` agent-rules block is auto-generated by `next dev` — don't hand-write it, just let it appear and commit it.
